# Checklist de cumplimiento

## Antes de conocer el reto
- [x] Crear repositorio público, solo con información publicable.
- [ ] Elegir liderazgo general (no necesariamente quien figura como coordinador).
- [ ] Confirmar disponibilidad, responsabilidades y revisores.
- [ ] Establecer sistema de seguimiento con Issues o Projects.
- [ ] Revisar bases y condiciones de propiedad intelectual.
- [ ] Preparar inventario de activos previos y licencias.
- [ ] Acordar canal privado para cualquier información restringida.

## Al conocer el reto
- [ ] Confirmar enunciado por canal oficial y determinar si puede publicarse.
- [ ] Identificar problema, resultado esperado, usuario, línea base, KPI, recursos y restricciones.
- [ ] Evaluar alternativas con matriz de puntuación de la fase virtual.
- [ ] Definir funcionalidad crítica nueva y su factibilidad en dos jornadas.
- [ ] Preparar Solution Concept sin confundir hipótesis con datos verificables.

## Presencial
- [ ] Preservar commit de estado anterior al evento.
- [ ] Registrar desarrollo nuevo o adaptación sustantiva.
- [ ] Ejecutar y documentar pruebas reproducibles.
- [ ] Validar impacto con datos permitidos y supuestos explícitos.
- [ ] Entregar historial, prototipo funcional y presentación.
